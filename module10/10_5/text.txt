Давайте вспомним, как работает память в компьютере (речь идёт об оперативной памяти, в которой хранятся все переменные, объявленные в коде).

Память компьютера построена из двоичных запоминающих элементов — битов (0 или 1), объединённых в группы по 8 битов, которые называются байтами. Для понимания можно представить огромную таблицу, в которой каждая ячейка может принимать значение 0 или 1. Каждая такая ячейка пронумерована, и мы можем узнать её значение по номеру (либо присвоить новое).

Поэтому, когда вы объявляете какую-то переменную типа int64, где-то в этой таблице резервируется 64 бита (то есть 8 байтов). А когда присваиваете ей какое-то число, то в эти ячейки записывается это число (преобразованное в двоичную систему счисления, разумеется).

Примерно то же самое происходит каждый раз, когда вы работаете с переменными других типов. Конечно, есть ещё много пропущенных нюансов, но для понимания текущей главы предлагаем вам запомнить такую простую абстракцию:

Память — это последовательность байтов с порядковым номером.
Когда вы объявляете переменную, то выделяется какое-то (зависит от типа переменной) количество ячеек в памяти.
Когда вы присваиваете переменной значение, оно каким-то образом кодируется в двоичное представление и сохраняется в эту выделенную память.
Когда вы читаете значение переменной, по индексу ячейки происходит чтение из памяти.
Теперь, когда мы будем разбирать преимущества и недостатки различных типов данных, вы можете вернуться к этой абстракции и понять, почему что-то работает быстрее, а что-то требует меньше памяти.

Что такое структуры данных? Как вы уже знаете, компьютер хранит информацию в байтах, которые образуют собой двоичную последовательность. В таком формате, конечно, можно записать любую информацию, однако человеку работать с этим будет неудобно. Поэтому умные, но ленивые люди начали придумывать и реализовывать в языках программирования всякие абстракции, которые упростили бы работу с данными.

В первую очередь это, конечно, типы данных, с которыми вы уже знакомы: int, string и так далее. Это уже более удобный инструмент, но очевидно, что только его недостаточно. Много всего было изобретено для удобства, но в этой главе мы сконцентрируемся именно на структурах данных.

Структура данных — это контейнер, который хранит данные в определённом формате (с определённой структурой).

Когда мы говорим про структуры данных, чаще всего мы подразумеваем работу со множеством однотипных или логически связанных данных. Для каждой структуры данных обычно реализуются типичные операции, которые с ней можно совершать (например, чтение или добавление новых элементов).

Различные структуры данных имеют свои преимущества и недостатки: какие-то работают быстрее в одном случае и медленнее в другом, какие-то наоборот. Некоторые удобнее для решения одних задач, некоторые — для других.

Некоторые структуры данных (например, массив) занимают в памяти постоянный объём, поэтому их называют статическими структурами. Другие структуры (например, список или дерево), которые могут изменять свою длину, называются динамическими структурами.

В этом уроке мы рассмотрим основные структуры данных (говорить про них мы будем именно в разрезе Go, в других языках программирования какие-то детали могут отличаться):

Массив
Массив (англ. array) — это последовательность фиксированной длины из нуля и более элементов определённого типа.

Представьте почтовые ящики в многоквартирном доме, это хорошая аналогия массива. Есть множество ячеек (ящиков), и у каждого есть свой номер (у массива это индекс). Используя номер ящика, почтальон кладёт туда письмо (запись элемента в массив по индексу), а жители дома забирают их оттуда (чтение из массива).

img

Массив — это самая фундаментальная структура данных как в Go, так и в других языках программирования. Его использование лежит в основе многих других структур данных.

Типичные операции для массива:

Чтение элемента по заданному индексу,
Запись элемента по заданному индексу,
Удаление элемента по заданному индексу,
Получение размера массива.
Обычно используется для хранения какого-то множества объектов, в которое редко добавляются или удаляются элементы.

Плюсы
По массиву (отсортированному) приемлемо быстро работает поиск (бинарный поиск имеет сложность O(n log(n)).
Быстрая операция чтения O(1).
Минусы
Массив занимает последовательный участок в памяти заранее определённого размера. Если нужно увеличить размер массива, то память придётся выделить заново. Мы не можем просто забрать память, следующую за уже выделенной, по ряду причин. Одна из причин заключается в том, что эта память может быть уже занята другим объектом.
В Go массив реализован как тип array и обёртка над типом array — slice.

Список
Список (англ. list) — это последовательность элементов, где каждый элемент может быть связан с другим с помощью ссылки на следующий и/или предыдущий элемент.

*Также называется «связный список» (англ. linked list).

img

Элемент списка обычно имеет какое-то поле, в котором хранятся данные (payload). Элементы списка также называют узлами.

Список — это частный случай графа (ниже прочитаете, что такое граф). Элементы в списке необязательно занимают непрерывный участок памяти. Элемент, который используется для «входа» в список, называется корневым.

Списки бывают однонаправленными: в таком случае каждый элемент хранит указатель на следующий элемент в списке. Последний же элемент указывает на NULL.

img

Списки могут быть двунаправленными: каждый элемент хранит два указателя, где один указывает на предыдущий элемент, а другой — на следующий.

img

Списки могут быть круговыми: если один из элементов указывает на какой-то из предыдущих.

img

Типичные операции для списка:

Вставка элемента,
Удаление элемента,
Поиск элемента.
Обычно используется на собеседованиях начинающих разработчиков. На самом деле, этот тип бывает полезным, когда вы храните большое количество данных постоянно изменяющегося размера. У этого типа «дешевые» операции добавления и удаления (потому что нам не нужно создавать список заново, мы просто переопределяем значение указателя), но достаточно дорогой «поиск». Также данные хранятся в памяти не последовательно, и при удалении элементов память очищается.

В Go реализация списка есть в модуле container/list.

Очередь
Очередь (англ. queue, читается как «кюу», а не как «кьюуеуе») — абстрактный тип данных, представляющий собой множество элементов, организованных по принципу FIFO (англ. first in — first out, первым пришёл — первым вышел).

Очередь легко представить. Представьте очередь в магазине. Очередь в информатике работает по такому же принципу. Первый человек, который встал в очередь, будет обслужен первым, последний — последним. Если необходимо обслужить человека из середины очереди, то вначале нужно обслужить всех предыдущих.

Типичные операции для очереди:

Добавление элемента в конец,
Забрать первый элемент.
Обычно используется, когда нужно совершить какие-то действия в порядке их поступления, выполнив их последовательно. Например, можно записать историю игры в шахматы: каждый раз, когда игрок делает ход, записывать его в очередь, а потом, когда нужно будет воспроизвести партию, забрать поочередно все ходы из очереди.

В стандартной библиотеке Go нет имплементации очереди (тому есть ряд причин, среди которых нет «лени разработчиков»).

Стэк
Стэк (англ. stack) — абстрактный тип данных, представляющий собой множество элементов, организованных по принципу LIFO (англ. last in — first out, последним пришёл — первым вышел).

Обычно, когда в учебниках описывают стэк, предлагают представить стопку тарелок. Для того чтобы избежать банальных аналогий, мы предлагаем вам представить пистолетный магазин. Патроны в него добавляются по одному, а первым из пистолета вылетит патрон, который поместили в магазин последним. Иначе никак. Если вы охотитесь на вампиров и случайно первым в магазин положили серебряный патрон, а потом — свинцовые, то придётся выпустить все остальные пули, перед тем как получится серьёзно ранить нечисть.

Типичные операции для стэка:

Добавление элемента в конец,
Забрать последний элемент.
Обычно используется, как и в случае с очередью, для обеспечения порядка: например, для операции отмены последнего действия (Ctrl + Z).

В стандартной библиотеке Go нет имплементации стэка (тому есть ряд причин, среди которых нет «лени разработчиков»).

Графы
Теория графов — это также огромный раздел на стыке математики и информатики. Многие определения в этом пункте будут преподноситься упрощёнными.

Граф моделирует набор связей. Графы состоят из узлов (они же вершины) и рёбер (они же дуги). Узел представляет собой какую-то сущность, а рёбра указывают на связи. Узел может быть напрямую соединён с несколькими другими узлами. Эти узлы называются соседями.

Всё, переходим к следующей структуре.

Шутка.

img

На этой картинке кружочки — это узлы, а линии — это рёбра. Представим, что A, B, C, D, E — это названия городов, а рёбра — это дороги между ними. Из A можно напрямую попасть в B и C, а в город E можно добраться только через город D. Вот мы и смоделировали связи между городами.

Теперь представим, что A, B, C, D, E — это имена пользователей в социальной сети «Всоциуме», а рёбра означают, что они подписаны друг на друга. Мы видим, что A, B и C — довольно общительные ребята, из которых B знаком с не очень социально активным D, который является другом E, который и вовсе социопат, судя по всему. Теперь мы смоделировали связи между пользователями социальной сети.

Думаю, идея понятна. «Но зачем это нужно?» — вероятно, спросите вы. Дело в том, что для графов умные люди придумали множество алгоритмов, которые позволяют решать различные задачи. Например, найти кратчайший путь между вершинами графа (привет, Дейкстра). Как вы думаете, как работают навигаторы? А ещё, по вашему мнению, насколько легко реализовать автоматический поиск маршрута на карте без использования графов? Сложно, поверьте на слово.

Давайте запомним ещё несколько фактов о графах.

img

Рёбра графа могут иметь направление (вместо линии рисуется стрелочка). В таком случае из города C не будет прямой дороги в город A, а попав в город E вы останетесь в нём навсегда!

img

Рёбра графа могут иметь вес.

В случае с городами вес будет указывать на расстояние или на время, необходимое, чтобы пройти это расстояние. Может иметь разное значение, в зависимости от условий и задачи.

Вес может быть отрицательным.

Граф, содержащий рёбра между всеми парами вершин, является полным.

Обычно используются… Много где. Кучу различных задач можно эффективно решать с помощью графов. Почитайте тут, например.

Дерево
Дерево является частным случаем графа.

Дерево — это связный ациклический граф. Связность означает наличие маршрута между любой парой вершин, ацикличность — отсутствие циклов.

img

Думаю, вы слышали про выражение «фамильное дерево». Когда где-то вверху фотография самого древнего родственника, и от него идут стрелочки вниз, указывающие на его потомков. Ну вот это оно и есть.

Элемент дерева называют узлом.
Узлы, на которые указывает узел, называют потомками этого узла.
Узел, который указывает на другой узел, называют родительским для узла, на который он указывает.
Узел, который не является ничьим потомком, называют корнем (англ. root) дерева.
img

Чем-то дерево похоже на уже известный вам тип Список (который тоже является графом, кстати), только у каждого элемента вместо указателя на следующий элемент (или указателей на следующий и предыдущий элемент) указатели (во множественном числе, их может быть от нуля до бесконечности) на родительские элементы.

В информатике достаточно редко используются простые деревья. Поэтому рассмотрим следующие новые понятия:

Бинарное дерево — это дерево, в котором у каждого узла существует не более двух потомков. На картинке как раз пример бинарного дерева.

Бинарное дерево поиска — это бинарное дерево, у которого значение левого потомка меньше значения родителя, а значение правого потомка больше значения родителя для каждого узла дерева.

На картинке как раз пример бинарного дерева поиска. Как удачно совпало! Надеюсь, пока всё просто для понимания. Потому что нужно ввести ещё одно определение.

Сбалансированное бинарное дерево поиска — это бинарное дерево поиска с логарифмической высотой, поиск по которому будет иметь сложность O(log(n)).

Представьте себе, на картинке как раз пример сбалансированного бинарного дерева поиска! Приведённое выше определение не является строгим, но оно отлично передаёт суть. Чтобы бинарное дерево поиска стало сбалансированным, применяются специальные методы балансировки, но в рамках этого урока не получится об этом рассказать.

img   Дополнительно
Кому интересно, можете почитать об этом.

Бинарное дерево поиска, как следует из названия, обычно используется для поиска. Сложностью поиска по сбалансированному бинарному дереву поиска является O(log(n)).

На самом деле, бинарный поиск (это такой алгоритм поиска, о нём поговорим в следующих уроках подробнее) по отсортированному массиву имеет такую же сложность, но при этом структура проще и понятнее, так зачем использовать СБДП?
